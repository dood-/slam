# Domain Docs

## Before exploring

Read root `GLOSSARY.md`, when present, and ADRs in `docs/adr/` relevant to the work. This is a single-context project.

If these documents do not exist, proceed silently. Create them lazily through domain-modeling when terms or architectural decisions are resolved.

## Vocabulary

Use the glossary's terms in specifications, issues, code discussions, and tests. If a needed concept is absent, first check whether an existing term covers it; record a real terminology gap for domain-modeling.

## Decisions

Respect relevant ADRs. If a proposal conflicts with an ADR, identify that ADR and explain why the decision should be reopened.
