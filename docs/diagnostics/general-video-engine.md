# Уточнённое требование: заранее неизвестные видео

2026-11-06. Пользователь уточнил, что нужен общий алгоритм для следующих неизвестных видео. Ручной выбор удачного начального участка и привязка к нему не удовлетворяют этому требованию. Подбор профиля по одному ролику также не является проверкой обобщения.

## Вычислительная база

Прямой read-only `nvidia-smi` вне ограниченного sandbox подтвердил: NVIDIA GeForce RTX 3060, 12288 MiB VRAM, драйвер 617.42. Раннее сообщение NVML `GPU access blocked` относилось к ограничениям доступа инструмента, а не доказывало отсутствие доступной GPU. Выбор CPU-only больше не следует считать требованием пользователя.

## Пересмотр выбора движка

COLMAP остаётся работоспособным офлайн-кандидатом и контрольным методом, но текущие эксперименты не подтверждают правильность его траектории на тестовом ролике. Выбор по готовым wheels и покрытию кадров оказался недостаточен для основной цели.

Первый кандидат для следующего сравнительного испытания — **MASt3R-SLAM**: monocular SLAM с learned 3D priors, tracking, graph/loop closure, режимами с известной калибровкой и без неё. Он принимает MP4. Установка использует Python/PyTorch, CUDA и native extensions. Upstream эксперименты проводились на RTX 4090; пригодность по памяти/скорости на RTX 3060 12 GiB необходимо измерить, не обещать заранее. Лицензия проекта CC BY-NC-SA 4.0; условия весов отдельные. Это ограничивает выбор для коммерческого продукта.

DROID-SLAM — сравнительный кандидат для известной/независимо проверенной калибровки. Upstream требует calibration file на своих данных и ≥11 GB VRAM для demo inference. Он не решает задачу неизвестной калибровки в одиночку.

Пока ни MASt3R-SLAM, ни DROID-SLAM не установлены и не прогнаны на пользовательском видео. Они не объявляются решением по одной статье/README.

## Общий pipeline

Видеодекодирование и точные timestamps → автоматический выбор ключевых кадров → SLAM и восстановление после потери tracking → согласованная траектория и диагностика → существующая Vue-панель.

Не использовать ручные anchors отдельного ролика как обязательный вход. При известной камере применять её калибровку; для неизвестной использовать поддерживаемый движком режим и явно учитывать неопределённость. Контроль согласованности и качества необходим, но не доказывает правильность физического пути.

Оставить Vue/FastAPI и контракт результата; экспериментальный GPU-движок изолировать собственным окружением/адаптером. Очередь и БД для этой смены не нужны.

## Проверка обобщения

Сравнить одинаковую конфигурацию на независимых видео разных сцен/движений, не выбирать результат по максимальной регистрации кадров. Добавить последовательность с известным маршрутом для ATE/RPE с явно заданным similarity alignment и несколько видео без разметки для качественной проверки. Потерю tracking и несвязанные участки сохранять как таковые. Полностью корректная траектория из любого произвольного MP4 не обещается.
