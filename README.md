# Траектория камеры из видео

Локальное приложение: MP4 → COLMAP на CPU или cuVSLAM Mono на NVIDIA GPU → синхронные видео и маршрут во Vue. Один запуск одновременно, без очереди и базы данных. Результаты сохраняются в файлах.

## Запуск

Проверено на Linux/WSL, Python 3.13 и Node 22.22. Нужны [uv](https://docs.astral.sh/uv/) и Node 22 LTS (от 22.12) либо Node 24+. Для COLMAP собственный C++ и CUDA не требуются; cuVSLAM устанавливается отдельно.

Из корня проекта:

```sh
make
```

Команда установит зависимости из lock-файлов, соберёт frontend и запустит оба сервера. Открыть **http://127.0.0.1:4173**. `Ctrl+C` останавливает оба сервера. Зависимости устанавливаются повторно только при изменении соответствующих `pyproject.toml`, `package.json` или lock-файлов.

Для разработки: `make dev` (**http://127.0.0.1:5173**). Frontend обновляется при изменении файлов; API работает без reload. Другие порты: `make run API_PORT=8001 WEB_PORT=4174`. Все команды: `make help`. Для совместного запуска нужны GNU Make, Bash и `setsid` из util-linux (Linux/WSL).

Можно запустить серверы вручную. В первом терминале:

```sh
uv sync --project backend --locked
uv run --project backend uvicorn slam.api:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```sh
cd frontend
npm ci
npm run build
npm run preview -- --host 127.0.0.1 --port 4173
```

Открыть **http://127.0.0.1:4173**. Для разработки вместо build/preview используйте `npm run dev`. Vite проксирует `/api` к localhost:8000. OpenAPI доступен на http://127.0.0.1:8000/docs.

Выберите MP4, проверьте предпросмотр, укажите «Движок обработки» и нажмите «Восстановить маршрут». После обработки доступны выбор модели, 2D-проекции, 3D-вид с ориентацией камеры, переход по времени, покрытие и JSON/CSV. Сохранённые результаты открываются в нижней части панели; движок виден в списке и над открытым результатом. Выбор движка для нового запуска не меняет открытый результат.

## cuVSLAM в панели

На Ubuntu 22.04 с Python 3.10 и драйвером NVIDIA выполните один раз:

```sh
bash tools/cuvslam/setup.sh
```

Перезапустите приложение и выберите **cuVSLAM Mono · GPU**. Движок принимает все кадры нового MP4; параметры CPU/SIFT и частота выборки к нему не применяются. Начальные настройки: длинная сторона 960 px, «Фокус / ширина» 0,8. Последнее — гипотеза о камере, не измеренная калибровка; масштаб остаётся условным. 3D-точки и репроекционная ошибка не экспортируются. Если окружения нет, пункт недоступен; API возвращает `503 engine_unavailable` при прямом запросе.

По умолчанию используется окружение `storage/experiments/cuvslam/.venv`. `SLAM_CUVSLAM_PYTHON=/absolute/path/to/python` задаёт другой интерпретатор с cuVSLAM **17.0.1+cu12** и зависимостями. API не загружает CUDA в свой процесс; GPU-worker запускается отдельно и поддерживает прогресс и отмену. Установка окружения не гарантирует доступ к GPU: ошибки CUDA возвращаются как ошибка обработки, без скрытой замены на COLMAP.

## Хранение и жизненный цикл

По умолчанию всё находится в `storage/` в корне проекта: исходники в `videos/`, каждый запуск в отдельном каталоге `runs/` с настройками, логом, разреженной реконструкцией и manifest. `SLAM_STORAGE=/absolute/path` меняет хранилище. `SLAM_UPLOAD_LIMIT_BYTES` меняет лимит файла (по умолчанию 512 MiB). Входные видео и runtime-файлы исключены из Git.

Запускайте **один API-процесс, без `--workers` и reload во время обработки**. Второй запуск получает `409 processing_busy`. Отмена ждёт остановки дочернего процесса; следующий запуск создаёт новый каталог. При штатном и аварийном завершении API дочерняя обработка прекращается. После рестарта готовые результаты доступны, текущий запуск начинается заново вручную. Незавершённые каталоги не выдаются как готовые результаты.

Обработка может занимать минуты. На включённых в исследование роликах текущий профиль зарегистрировал 111/111 и 234/234 выбранных кадров. Это не подтверждение точности в метрах: у монокулярной реконструкции произвольный масштаб, оси не выровнены по гравитации, GPS отсутствует. Независимые модели не соединяются; на пропусках поза не подменяется ближайшей точкой. Восстанавливается движение камеры, включая движение руки.

## Проверки

Из корня:

```sh
uv sync --project backend --extra test --locked
uv run --project backend --extra test python -m pytest backend/tests -q
npm --prefix frontend test
npm --prefix frontend run build
```

Детерминированный E2E сам создаёт короткий H.264, запускает изолированные API и production preview на портах 18000/14173. Только тестовый сервер подменяет внешний CV-процесс контролируемыми позами; production использует выбранный настоящий движок.

```sh
cd tests/e2e
npm ci
npx playwright install chromium
npm test
```

На Linux браузеру также нужны системные зависимости Playwright. Если установлен рабочий Chromium, можно указать его: `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium-browser npm test`.
